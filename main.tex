\begin{abstract}
This report studies automatic video object removal under the AIAA3201 project setting. We build three progressively stronger pipelines: a hand-crafted baseline that combines YOLOv8-Seg, sparse optical-flow motion filtering, temporal background propagation, and OpenCV inpainting; an AI-driven reproduction using SAM 2 or VGGT4D masks with ProPainter; and an exploration stage using SAM 3 masks with ProPainter, DiffuEraser, and ROSE inpainting backends. We evaluate mask quality on all 90 DAVIS validation sequences using Jaccard mean (JM) and Jaccard recall (JR), and evaluate video restoration on paired Wild Video clips using PSNR and SSIM. SAM 2 is a strong Part 2 baseline (JM 0.9167, JR 0.9846), while the SAM 3 multi-object setup improves DAVIS mask quality to JM 0.9423 and JR 0.9952. The best Wild Video PSNR is achieved by SAM 3 + DiffuEraser, while SAM 3 + ROSE-SE yields the best SSIM. GitHub repository: \url{https://github.com/Chikit-WONG/AIAA3201-Introduction_to_Computer_Vision-Project}.
\end{abstract}

\section{Introduction}
Video object removal requires two coupled capabilities: the system must identify the foreground object that should be removed, and it must synthesize a plausible background in the missing region. This is harder than single-image inpainting because masks must remain temporally stable and the filled background must avoid frame-to-frame flicker. The project therefore exposes the main tension in video restoration: segmentation errors propagate into inpainting artifacts, while inpainting models can still fail even when the mask is accurate if the hidden background is never visible.

We organize the work into three parts. Part 1 implements a classical pipeline from first principles. It uses YOLOv8-Seg detections, Lucas-Kanade optical flow to reject static detections, mask dilation, temporal background borrowing, and a Telea inpainting fallback. Part 2 reproduces stronger open-source systems by pairing SAM 2 or VGGT4D masks with ProPainter. Part 3 explores stronger mask and generative restoration choices: SAM 3 is used as the tracker, and ProPainter, DiffuEraser, and ROSE are compared as inpainting backends.

\section{Related Work}
Object detection and instance segmentation provide the front end for object removal. R-CNN introduced region-based CNN detection \cite{girshick2014rcnn}, while Mask R-CNN added a mask branch for instance segmentation \cite{he2017maskrcnn}. YOLO formulated detection as a single-stage real-time prediction problem \cite{redmon2016yolo}, and DETR later cast detection as direct set prediction with transformers \cite{carion2020detr}.

Recent foundation models shift segmentation from fixed-category detection to promptable object selection and tracking. SAM \cite{kirillov2023sam} provides promptable image segmentation, Track Anything combines SAM with video memory propagation \cite{yang2023trackanything}, SAM 2 extends the promptable formulation to video \cite{ravi2024sam2}, and SAM 3 introduces concept-level segmentation \cite{carion2025sam3}. VGGT and VGGT4D mine geometric and motion cues from visual geometry transformers \cite{wang2025vggt,hu2025vggt4d}; Pi3 and MapAnything are relevant newer geometry foundation models \cite{wang2025pi3,keetha2025mapanything}.

For video inpainting, FGVC uses flow-edge guidance for video completion \cite{gao2020fgvc}, E2FGVI proposes an end-to-end flow-guided framework \cite{li2022e2fgvi}, and ProPainter improves propagation and sparse-transformer inpainting \cite{zhou2023propainter}. Generative alternatives include latent diffusion models \cite{rombach2022ldm} and conditional control such as ControlNet \cite{zhang2023controlnet}, which motivate our Part 3 DiffuEraser and ROSE trials.

\paragraph{Part 1: hand-crafted baseline.}
The baseline extracts person masks with YOLOv8-Seg and then applies Lucas-Kanade sparse optical flow inside each instance mask. If the mean feature displacement is below a threshold, the object is treated as static and removed from the mask. We dilate accepted masks to cover motion blur and boundary uncertainty. For restoration, the temporal variant searches nearby frames in a sliding window. With optical-flow alignment enabled, neighboring frames and masks are warped into the current frame coordinate system using Farneback dense flow before clean pixels are copied. Remaining holes are filled by \texttt{cv2.inpaint} with Telea inpainting.

\paragraph{Part 2: AI-driven reproduction.}
Part 2 tests two mask sources with the same ProPainter backend. SAM 2 receives first-frame prompts and tracks objects through the video. VGGT4D is used as a training-free motion-cue baseline, but its dynamic masks are less aligned with the object-removal objective. ProPainter then propagates valid content and applies transformer-based completion, giving a stronger temporal inpainting model than the Part 1 spatial fallback.

\paragraph{Part 3: optimization and extension.}
Part 3 uses SAM 3 as the mask tracker and compares five restoration variants: ProPainter, DiffuEraser, DiffuEraser with side-effect masks, ROSE, and ROSE with side-effect masks. The side-effect mask expands the object mask, adds a shifted shadow region, and can include reflection regions for scenes where removing only the visible object leaves secondary traces. We also upgraded SAM 3 initialization to use per-object masks instead of a single union mask, matching the multi-object prompting pattern used by SAM 2. This change improves tracking stability on DAVIS.

\paragraph{Implementation interface.}
The three parts are deliberately implemented with similar intermediate artifacts. Each pipeline writes extracted frames, binary masks, restored frames or videos, and metric summaries. This makes debugging more reliable: when a result fails, we can inspect whether the error first appears in mask extraction, temporal tracking, mask post-processing, or the restoration backend. It also prevents the evaluation from favoring one implementation simply because it stores outputs in a different format. For example, Part 1 produces masks from detection and motion filtering, Part 2 produces tracked masks from a first-frame prompt or motion cue, and Part 3 produces multi-object tracked masks plus optional side-effect regions; after that point, the evaluation code can consume all masks in the same binary-mask convention.

This shared interface also explains why Figure~\ref{fig:pipeline} uses three horizontal lanes instead of three unrelated diagrams. The lanes expose the actual variables under study. Part 1 asks how far hand-crafted motion filtering and temporal copying can go. Part 2 asks how much improvement comes from stronger promptable segmentation and a dedicated video inpainting model. Part 3 asks whether better object tracking and larger masks for shadows, blur, and reflections improve the final perceptual result. Keeping the input and output columns fixed avoids a misleading comparison where different videos, frame choices, or visualization styles hide the effect of the method itself.

\section{Experiments}
\paragraph{Datasets and metrics.}
We use the mandatory bmx-trees and tennis sample sequences, two paired Wild Video clips, and the full DAVIS validation set. DAVIS evaluation reports mask quality only: JM is mean IoU over frames and JR is the fraction of frames with IoU at least 0.5. For the Wild Video pair, clean no-person videos are available, so we report PSNR and SSIM against those clean references. Full-frame PSNR/SSIM on DAVIS would compare restored backgrounds against frames that still contain foreground objects, so it is not used for the formal DAVIS table.

The datasets play different roles in the analysis. DAVIS is useful for mask evaluation because it provides dense annotations over many object categories and motion patterns. The bmx-trees and tennis sequences are kept as required course cases and are also used for visual inspection because they contain thin structures, fast motion, and background details that reveal boundary errors. The paired Wild Video clips are smaller, but they are the only setting where a clean no-person target is available, so they are the proper source for PSNR and SSIM. We therefore avoid mixing incompatible metrics: DAVIS is used to measure segmentation quality, while Wild Video is used to measure restoration fidelity.

\paragraph{Wild Video restoration.}
Table~\ref{tab:wild-main} and Figure~\ref{fig:wild-chart} summarize the paired Wild Video metrics. Part 2 SAM 2 + ProPainter improves over all Part 1 variants, confirming that better video masks and temporal inpainting matter. In Part 3, DiffuEraser gives the highest PSNR, while ROSE-SE gives the highest SSIM. These metrics are useful but not complete: PSNR favors pixel-level agreement, whereas temporal flicker and perceptual sharpness still require visual inspection.

The Wild Video results also show why restoration should not be ranked by one metric alone. PSNR rewards conservative reconstructions that stay close to the clean reference in average pixel value, while SSIM is more sensitive to local structure. DiffuEraser obtains the best PSNR, suggesting that its generated background is close to the paired clean frame in a mean-squared-error sense. ROSE-SE obtains the best SSIM, which is consistent with a sharper local structure after applying the side-effect mask. However, neither metric directly measures temporal stability. A method can score well on individual frames and still flicker during playback if the generated texture changes from frame to frame.

For this reason, Figure~\ref{fig:part3-backends} is reported together with the numerical table. The backend comparison keeps the SAM 3 masks fixed and changes only the restoration stage, so the observed differences are attributable to the inpainting model and the side-effect mask. The side-effect mask is not expected to always improve PSNR, because it deliberately asks the model to synthesize a larger region. Its purpose is to remove traces that the object mask misses, such as shadow, reflection, or boundary blur. This trade-off explains why the best quantitative row and the most visually acceptable row may differ.

\paragraph{Failure analysis.}
The most visible remaining limitation appears when the mask covers a hard background for many frames. Figure~\ref{fig:rhino-failure} shows the rhino sequence, where the occluded grass and body-sized background region remain difficult. DiffuEraser tends to generate a plausible but blurred fill when the true background is never observed for long enough. ROSE can preserve stronger texture locally, but adjacent frames may change appearance, producing background flicker. This suggests that future work should combine generative keyframe repair with explicit temporal consistency losses, flow-guided propagation, or a post-hoc deflickering module.

This failure case separates two error sources. The first source is mask error: an incomplete mask leaves parts of the object, shadow, or reflection in the result. The second source is restoration ambiguity: even with a good mask, the hidden background may never be visible in nearby frames. Part 1 mainly fails through the first source, because the mask and optical-flow alignment are fragile. Parts 2 and 3 reduce this mask problem, but they still face the second source on long occlusions. Generative backends can hallucinate a plausible patch, but they do not know the true background and may change the hallucination across frames.

\paragraph{Practical discussion.}
The main practical lesson is that video object removal should be treated as a pipeline problem rather than as a single-model problem. A strong inpainting backend cannot fix an object remnant that is never included in the mask, and a strong mask tracker cannot guarantee a realistic fill when the background is permanently hidden. This is why the report keeps mask metrics and restoration metrics separate. DAVIS JM/JR tells us whether the method is selecting the right pixels to remove, while Wild Video PSNR/SSIM tells us whether the completed frame matches a clean reference. The two evaluations answer different questions and should not be collapsed into one score.

The second lesson is that temporal consistency is the main gap between visually plausible frame-level results and convincing video results. Part 1 uses explicit temporal borrowing, so it is interpretable but brittle. Part 2 uses ProPainter, which improves temporal propagation and reduces obvious frame-wise discontinuities. Part 3 adds generative backends, which can produce more plausible content inside large holes but may introduce new temporal variation because each synthesized region can drift. This explains why a model can improve PSNR or SSIM while still requiring qualitative video playback to detect flicker.

The side-effect mask is useful when the object has secondary traces, but it also increases the restoration difficulty. Expanding the mask can remove shadows, reflections, and boundary blur that would otherwise make the edited video look fake. At the same time, the backend must synthesize a larger area, so the result can become smoother or less faithful to the clean reference. In practice, this means the side-effect mask should be selected according to the scene. For a simple walking person with a stable background, the object mask may be enough. For reflective floors, strong shadows, or motion blur, a larger mask is more defensible even if pixel metrics do not always improve.

\paragraph{Part-by-part takeaways.}
Part 1 is valuable because it exposes every assumption in a video object removal pipeline. The detector decides which instances are even considered; the sparse optical-flow filter decides whether the instance is dynamic enough to remove; the dilation radius decides how much boundary uncertainty is tolerated; and the temporal propagation window decides how much neighboring evidence is available for filling. These choices are easy to inspect and modify, but they also create many failure points. A small detection miss or an incorrect motion threshold can propagate to the final inpainted video. This explains why the Part 1 results are useful as a baseline but not competitive with promptable video segmentation.

Part 2 is the strongest reproduction-style pipeline because it replaces several brittle hand-crafted decisions with learned temporal segmentation and learned video inpainting. SAM 2 provides object-consistent masks after a first-frame prompt, and ProPainter is designed for temporal content propagation rather than independent per-frame filling. The VGGT4D branch is still informative even though its mask metrics are low: it shows that not every strong visual foundation model is directly suitable for object removal. A motion or geometry cue must be converted into an object-specific removal mask, otherwise the inpainting model receives the wrong hole.

Part 3 is the most flexible pipeline because it separates three choices that are often coupled in end-to-end demos: mask tracking, side-effect mask construction, and restoration backend. SAM 3 improves the mask side of the task, while DiffuEraser and ROSE explore different generative restoration behaviors. This makes Part 3 a useful platform for ablation even when the final perceptual quality is mixed. The results suggest that the largest remaining gains will not come from simply swapping one backend for another, but from making the backend temporally aware of the mask history and the visible background evidence.

\paragraph{Evaluation limitations.}
The current evaluation is intentionally conservative. DAVIS gives high-quality segmentation ground truth, but it does not provide clean background frames for object-removal PSNR and SSIM. Wild Video provides paired clean references, but only for a small number of clips. As a result, the report combines broad mask evaluation with narrower restoration evaluation. This is a reasonable compromise for the course project, but it also means the tables should be read as complementary evidence rather than a complete benchmark.

Another limitation is that the report uses frame-level restoration metrics but discusses video-level artifacts. PSNR and SSIM are computed per frame and then averaged, so they cannot directly penalize temporal flicker. A future benchmark should include temporal metrics, such as warping the previous restored frame into the current frame with optical flow and measuring the error inside the edited region. User studies or side-by-side video playback would also be useful because small temporal changes can be more noticeable to humans than a modest difference in average PSNR.

\paragraph{Engineering lessons.}
The codebase structure matters for a project with three independently developed parts. Saving masks and restored frames as explicit intermediate outputs made it possible to reuse evaluation scripts and to diagnose failures without rerunning the whole pipeline. It also made the report figures easier to generate consistently. The revised qualitative figures use the same bmx-trees frame for all three parts for exactly this reason: when the file layout and visualization protocol are shared, visual differences are more likely to reflect algorithmic differences rather than plotting or dataset choices.

The same principle applies to the new pipeline figure. The figure is not only a decorative overview; it is a map of the repository. The left side corresponds to frame extraction and input videos, the center lanes correspond to the three implementation tracks, and the right side corresponds to restored outputs and evaluation scripts. This alignment between figure, code, and report text reduces ambiguity for the reader and makes the comparison easier to audit.

\section{Discussion and Future Work}
\paragraph{Future work.}
The most immediate extension is interactive correction. In the current pipelines, a first-frame prompt or automatic mask source is expected to remain reliable throughout the video. This assumption breaks when the target object changes appearance, leaves the frame, becomes occluded, or overlaps with a similar object. A practical system should allow mid-sequence re-prompting and then propagate the corrected mask forward and backward. This would keep the user effort small while preventing one early tracking error from damaging the entire video.

A second extension is mask uncertainty modeling. The present evaluation treats every mask as a binary decision, but object boundaries, motion blur, shadows, and reflections are naturally uncertain. Instead of using one fixed dilation radius or one manually designed side-effect mask, the pipeline could maintain a soft confidence map. Pixels with high object probability would be removed aggressively, while low-confidence boundary pixels could be handled with a softer blending or refinement step. This would make the system less sensitive to a single threshold and could reduce both object remnants and unnecessary background destruction.

A third extension is temporally consistent generative repair. DiffuEraser and ROSE can synthesize plausible image content, but the report shows that plausible individual frames are not enough for video. A stronger backend should condition on neighboring restored frames, optical-flow correspondences, or a persistent latent representation of the synthesized background. The goal is not only to fill the current hole, but to keep the generated texture stable as the camera and object move. This is especially important for grass, water, rails, and repeated patterns, where small frame-to-frame changes are easy to notice.

Finally, the evaluation protocol should be expanded. The current report already separates mask quality, paired-reference restoration quality, and qualitative examples, but future work should add temporal metrics and more paired videos. A useful benchmark would include clean references for multiple object sizes, camera motions, shadows, reflections, and long occlusions. It would also report both full-frame scores and edited-region scores, because full-frame PSNR can hide failures when the removed object covers only a small part of the image. With these additions, the project could move from a course comparison toward a more complete benchmark for practical video object removal.

From an engineering perspective, a deployable system should also expose intermediate quality checks. Before running a costly generative inpainting backend, the system can preview mask coverage, mask stability, and side-effect regions. If the mask is unstable, the user should correct the prompt before inpainting rather than discover the error after the final video is rendered. If the mask is stable but too tight, the system can recommend a side-effect mask. If the mask is too large, it can warn that the backend may over-smooth the background. These checks are simple, but they match the failure modes observed in this project.

Runtime is another practical concern. The classical pipeline is lightweight and easy to run on CPU, but its quality ceiling is low. The SAM 2 and SAM 3 pipelines require stronger hardware, yet they save manual editing time by producing coherent masks across frames. The generative backends are the most expensive part, so they should be used selectively: short clips, difficult holes, or final high-quality outputs benefit most from them. A pragmatic workflow would therefore use a fast mask preview, run ProPainter as a stable baseline, and reserve DiffuEraser or ROSE for cases where the baseline leaves visible artifacts.

Overall, the project suggests a staged editing workflow. First, obtain a temporally stable object mask. Second, decide whether secondary traces require mask expansion. Third, run a temporal inpainting backend and inspect playback rather than isolated frames. Fourth, use generative repair only where the temporal method cannot recover the hidden background. This staged view is more reliable than choosing one model name as the answer to video object removal, because the best choice depends on the video content, the object motion, and the desired trade-off between speed, stability, and visual realism.

For reproducibility, future versions should make every stage runnable from a single configuration file. The configuration should record the video path, prompt frame, prompt points or boxes, mask source, side-effect mask settings, inpainting backend, and metric options. This would make it easier to rerun the same experiment after changing only one component. It would also reduce ambiguity when comparing Part 1, Part 2, and Part 3 outputs, because each result could be traced back to the exact mask and backend settings that produced it. This is especially important for generative restoration, where small changes in preprocessing or mask size can noticeably change the output. The same configuration record would make failed cases easier to archive: instead of storing only a final video, the repository could store the exact commands and intermediate masks needed to reproduce the failure. It would also make ablations cleaner, because the only changed field would be the component under study. That discipline is important when evaluating visual pipelines, where a different prompt, frame index, or mask dilation can change the qualitative conclusion. It would also help future students extend the project without first reverse-engineering which scripts generated each table and figure. These metadata are lightweight compared with model checkpoints, but they make the experimental evidence much easier to inspect.

\section{Conclusion}
The experiments show that video object removal is mask-limited before it is inpainting-limited. The classical Part 1 pipeline is useful for understanding the mechanics of detection, motion filtering, temporal borrowing, and spatial fallback, but it cannot match promptable video segmentation. Part 2 confirms that SAM 2 + ProPainter is a strong practical baseline because it combines accurate video masks with a temporal inpainting model. Part 3 improves DAVIS mask quality with SAM 3 multi-object initialization and explores generative backends that improve Wild Video perceptual metrics.

The final system comparison also clarifies the trade-off between controllability and generative quality. The hand-crafted baseline is the easiest to inspect and debug, but it is constrained by detector categories and optical-flow assumptions. The SAM 2 + ProPainter reproduction is the most balanced pipeline in terms of reliability and implementation simplicity. The SAM 3 variants are strongest for mask tracking and allow more flexible side-effect handling, but the inpainting backend still determines whether the final video looks temporally stable.

The main limitation remains long-duration occlusion: when the true background is hidden for many frames, generative methods can blur, and video diffusion methods can flicker. Future work should add mid-sequence re-prompting, uncertainty-aware mask correction, and temporally consistent generative refinement. A stronger follow-up would also evaluate temporal consistency directly, for example by measuring frame-to-frame warping error in the restored region, because PSNR and SSIM alone cannot fully describe video-level artifacts.
